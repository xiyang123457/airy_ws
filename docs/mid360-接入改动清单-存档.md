# MID360 接入改动清单

本文列出把 Livox MID360 接入当前开发环境需要做的全部改动。内容分三部分：结论变更、待确认事项、分步改动。

---

## 一、前提变更

用户于 2026-09-27 确认三项事实，与既有记录不符，后续操作以此为准。

| 项 | 原记录 | 实际情况 |
|---|---|---|
| 目标雷达 | RoboSense AIRY | **Livox MID360** |
| 宿主系统 | Ubuntu 22.04 | **Ubuntu 24.04**（容器内仍是 22.04 底子的 Humble） |
| 接入方式 | 网口 | 网口（确认一致） |

### 1.1 目标雷达为 MID360

`D:\up70\airy_ws` 整个项目是为 RoboSense AIRY 建立的，驱动为 `rslidar_sdk`。MID360 是 Livox 产品，驱动是 `livox_ros_driver2`，两者没有共享配置。

`rslidar_sdk` 不支持 MID360。现有 `src/rslidar_sdk/config/config.yaml`（`msop_port: 6699` / `difop_port: 7788`）、`launch/humble_start.py` 对 MID360 全部无效。

### 1.2 宿主系统为 Ubuntu 24.04

ROS2 Humble 的官方二进制包只覆盖 Ubuntu 22.04，24.04 的 apt 源里没有 `ros-humble-*`。当前的 Docker 方案绕开了这一点：容器基于 `ros:humble-ros-base`，内部仍是 22.04 底子，与宿主发行版无关。

由此产生的影响：

- 宿主上不能直接 `apt install ros-humble-*`
- 想在宿主原生编译 `livox_ros_driver2`，只能走源码编译或改用 Jazzy
- 接雷达的网卡在宿主上，容器要能收到该网卡的 UDP

### 1.3 网络层的结论随平台改变

`network_mode: host` 在两个平台上语义不同：

| 平台 | 容器能否收到物理网卡 UDP |
|---|---|
| Windows + WSL2 + Docker Desktop | 否。host 模式落到 WSL2 虚拟网络命名空间，物理网卡广播进不来 |
| Ubuntu + Docker | 是。host 模式直接复用宿主网络栈 |

所以在 Ubuntu 上不需要为网络模式做特殊处理，Windows 上那一套 mirrored 网络、端口映射的讨论不再适用。

## 三、分步改动

### 第一步 · 确认宿主机器

```bash
uname -a                    # 确认内核与发行版
ip -br addr                 # 查看有线网卡名与当前 IP
ls /mnt/                    # 有 Windows 分区说明当前是 Windows
```

### 第二步 · 配置网卡 IP

网卡 IP 必须与雷达同网段。以网卡名 `enp3s0`、IP 设为 `192.168.1.50` 为例：

```bash
sudo nmcli con mod enp3s0 ipv4.method manual ipv4.addresses 192.168.1.50/24
sudo nmcli con up enp3s0
ip -br addr show enp3s0     # 回读确认
```

MID360 出厂默认网段为 `192.168.1.x`，掩码 `255.255.255.0`，网关 `192.168.1.1`。

### 第三步 · 放行防火墙

```bash
sudo ufw status
sudo ufw allow 56100/udp    # 点云数据
sudo ufw allow 56200/udp    # 命令与控制
sudo ufw allow 56400/udp    # IMU 数据
```

要点：Docker 运行时会向 `iptables` 插入自己的规则，若抓不到包需同时检查 `iptables -L`。这几个端口是 Livox 默认值，与 AIRY 的 6699/7788 完全不同，不要混用。

### 第四步 · 验证物理链路

```bash
ping 192.168.1.1xx          # 换成雷达实际 IP
sudo tcpdump -i enp3s0 udp port 56100 -c 10
```

`tcpdump` 抓到包是唯一可信的判据。驱动未报错不等于链路正常——无数据时驱动同样会持续输出超时信息。

### 第五步 · 获取驱动源码

```bash
mkdir -p ~/mid360_ws/src && cd ~/mid360_ws/src
git clone https://github.com/Livox-SDK/livox_ros_driver2.git
```

### 第六步 · 编译

Livox 官方提供 `build.sh`，需指定 ROS 版本：

```bash
cd ~/mid360_ws/src/livox_ros_driver2
./build.sh humble            # 容器内为 Humble
```

注意：`livox_ros_driver2` 依赖 `livox_sdk2`，其 CMake 会自行拉取或需预先放置，编译失败时优先看这一项。容器内编译还需补装该包要求的依赖。

### 第七步 · 修改 MID360_config.json

配置文件位于 `livox_ros_driver2/config/MID360_config.json`。需修改的字段：

| 字段 | 含义 | 取值 |
|---|---|---|
| `host_net_info` 下的 IP | 本机接收地址 | 第二步设置的网卡 IP |
| `lidar_configs[].ip` | 雷达自身 IP | 实测确认的雷达 IP |
| `host_net_info` 下各端口 | 数据接收端口 | 默认 56100 / 56200 / 56400 |

```json
{
  "host_net_info": {
    "cmd_data_ip": "192.168.1.50",
    "push_data_ip": "192.168.1.50",
    "point_data_ip": "192.168.1.50",
    "imu_data_ip": "192.168.1.50"
  },
  "lidar_configs": [
    { "ip": "192.168.1.1xx" }
  ]
}
```

要点：`host_ip` 与网卡实际 IP 不一致是最常见的收不到数据的原因。多台雷达时 `lidar_configs` 需并列多条，每台一个 IP。

### 第八步 · 启动并验证

```bash
ros2 launch livox_ros_driver2 msg_MID360_launch.py
ros2 topic hz /livox/lidar
ros2 topic hz /livox/imu      # 若启用了 IMU
```

有频率输出即接入成功。无输出时依次回查：第四步 `tcpdump`、第七步 `host_ip`、第二步网卡 IP。

### 第九步 · 若需在容器内运行

`airy_ws` 的容器框架（Dockerfile / docker-compose.yml / devcontainer.json）本身可复用，但要替换容器内的包。需要处理：

- `Dockerfile` 中 `COPY src/` 与构建期 `colcon build` 的对象改为 `livox_ros_driver2` 工作空间
- `docker-compose.yml` 中外层工作空间挂载路径改为 MID360 工作空间
- `network_mode: host` 保留（Ubuntu 上是真宿主网络，正是所需）
- 移除 AIRY 专属的 `ros-humble-rmw-cyclonedds-cpp` 相关前提（该项是 `humble_start.py` 的要求，MID360 的 launch 不涉及）

### 第十步 · 修 airy_ws 的 git 子模块问题（若该项目继续使用）

`src/rslidar_sdk` 目前是 gitlink（子模块指针）但没有 `.gitmodules`，导致该目录在 checkout 后变空。驱动源码已于 2026-09-27 重新 clone 回本地，指针问题未修。

```bash
cd D:/up70/airy_ws
git rm --cached src/rslidar_sdk          # 摘出索引，不删文件
# 在 .gitignore 中加入 src/rslidar_sdk/（若决定不纳入版本管理）
git add -A && git commit -m "修正 rslidar_sdk 子模块指针为普通目录"
```

要点：不要把 `src/rslidar_sdk` 继续当作子模块管理，除非补上 `.gitmodules` 并保证 `git submodule update --init` 能正常执行。

## 四、执行顺序

```
Q1 / Q2 确认
  ↓
第一步  确认宿主机器与网卡
  ↓
第二、三步  配 IP、放行防火墙
  ↓
第四步  tcpdump 抓包          ← 卡住就停在这一步，不要往编译走
  ↓
第五、六步  拉源码、编译
  ↓
第七步  改 MID360_config.json
  ↓
第八步  launch，看 /livox/lidar 频率
  ↓
第九步  按需容器化
```

第四步是分界线。抓不到包时编译再成功也没有意义，问题必然在 IP、网线或防火墙三者之一。
